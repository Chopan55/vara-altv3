# VARA — Principios de producto

Si una tarea choca con estos principios, el Manager debe decir `ASK_PANCHO` en lugar de resolverlo solo.

1. **Honestidad antes que impacto.** Si no hay base para opinar, VARA lo dice ("información insuficiente"). Nunca se inventan comparables, cifras ni resultados. Datos de prueba solo dentro de tests y siempre rotulados como tales.
2. **Precio publicado, no valor de mercado.** Se compara contra avisos publicados; se aclara que son precios pedidos.
3. **Evidencia inspectable.** Cada conclusión se puede abrir y discutir; lo que falta se muestra y se convierte en acciones.
4. **Una próxima acción.** Cada pantalla guía a una acción principal, no a un menú de diez.
5. **Los números los calcula código determinístico.** La IA explica lo ya calculado; una respuesta con números ajenos al análisis se descarta.
6. **Privacidad por defecto.** No se guardan teléfonos ni datos de vendedores; compartir un análisis no incluye datos privados; los logs no contienen datos personales.
7. **Falla cerrado cuando hay gasto o riesgo.** Sin lista de IA (`AI_ALLOWED_EMAILS`) nadie usa la IA paga; sin credencial, la función se apaga con un mensaje honesto.
8. **Costo externo USD 0 salvo aprobación explícita de Pancho.** Excepción vigente: OpenAI hasta USD 20, solo para el email del dueño y con tope diario.
9. **Español rioplatense** (vos/tenés), tono directo y claro, sin tecnicismos innecesarios para quien no es técnico.
10. **Accesibilidad.** Se respeta "reducir movimiento"; todo control tiene etiqueta; el color no es el único portador de información.
11. **Una cosa a la vez.** Cambios chicos y revisables. Nada de "ya que estamos". Nuevas funciones solo si el objetivo las pide.
12. **No prometer lo que no existe.** Ningún botón, menú o texto debe anunciar una función que no funciona.
13. **Reversible.** Todo cambio se puede deshacer con un revert; las migraciones son aditivas e idempotentes.
